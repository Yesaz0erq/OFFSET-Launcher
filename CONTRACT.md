# OFFSET 0.9 internal module contract

Original FASM 1.73 Win32 application, x86 PE GUI. Include `win32ax.inc`, `mod_types.inc` and `version_types.inc` before module sections. Procedures are stdcall (`proc` / `invoke` for API, `stdcall` for internal). Each module owns data/code sections with unique names; main includes modules before the final imports section. Keep uninitialized buffers after initialized data, and keep code sections nonempty when FASM omits unused procedures. JSON and identities are UTF-8; filesystem paths are UTF-16. The launcher has no C / JavaScript / PowerShell runtime. Minecraft and official Forge/NeoForge installers use a separately installed Java runtime; Windows `tar.exe` extracts native libraries, installer metadata and independently validated modpack archives.

## Globals defined by main.asm
`hWnd dd 0`; `gameDir rw 1024`; `javaPath rw 1024`; `playerName rb 64`; `selectedVersion rb 128`; `memoryMb dd 4096`; `onlineMode dd 0`; `clientId rb 128`; `authName rb 64`; `authUuid rb 64`; `authToken rb 8192`; `authReady dd 0`.

`SetStatusA pUtf8`: translates known status labels through `LangTrA`, copies converted UTF-8 to UI status and posts WM_APP+1. Safe from worker. `SetStatusA` should never receive tokens.

## common.inc (network/JSON agent)
- `HttpRequest pUrlW, pMethodW, pHeadersW, pBodyA`: returns HeapAlloc NUL-terminated UTF-8 buffer in eax or 0. Body optional; GET method null defaults GET. HTTPS only in production. `httpStatus dd` global. Response max 32MB. `FreeMem ptr` releases on process heap. `HttpDownload pUrlA, pPathW, pSha1A`: UTF8 URL, Unicode destination; hashes expected sha1 if nonzero, creates parent dirs; returns 1/0. Must stream large files. `EnsureDirectory pPathW` recursive.
- JSON token parser: `JsonParse pUtf8` returns context ptr or 0; `JsonFree ctx`; `JsonRoot ctx` returns token ptr; `JsonGet ctx, token, pKeyA` returns child token ptr or 0; `JsonAt ctx, token, index`; `JsonCount ctx, token`; `JsonString ctx, token, pDestA, capacity` (unescape); `JsonInt ctx, token` returns int. Token pointers opaque. String return full required length on truncation or copied length; callers use suitably bounded buffers.
- `JsonKeyAt` / `JsonValueAt` enumerate object fields; `JsonNext` skips a subtree. `JsonRaw ctx, token, dest, capacity` copies the original JSON representation, including quotes for strings, and returns its full required length. `JsonBool` returns 1/0 for boolean values and -1 otherwise. Check lengths, termination and decoded embedded NULs before using strings as IDs, paths or URLs.

## memory.inc and mc_sources.inc
- `MemoryDetect` sets the MiB limit from `GlobalMemoryStatusEx.ullTotalPhys`; `MemoryParseW` and `MemoryValid` enforce decimal and physical-memory bounds. Do not impose a fixed 32/64 GiB cap.
- `McMirrorUrl urlA, destA, capacity, kind, variant` maps only recognized Mojang/Minecraft HTTPS hosts to BMCLAPI. `McDownload urlA, pathW, sha1A, kind` uses a stack-local URL buffer and tries mirrors before the original URL; kind 0 is metadata/client/index, 1 is libraries (`/maven`, then `/libraries`), and 2 is assets (`/assets`). Keep SHA-1 verification, atomic downloads, cancellation and cache reuse in `HttpDownload`.
- `McManifestRequest versionA` uses the SHA-1-bearing v2 manifest. An invalid or stale mirror falls back to Mojang. A valid official list may omit the target so the engine can report an unknown version. Authentication and mod requests do not pass through this source mapper.

## engine.inc (engine agent)
- `EngineInit` resolves gameDir default EXE sibling `.minecraft` and Java path via JAVA_HOME / SearchPathW if unset; creates directories.
- `EngineScanVersions hCombo` populates the installed-profile selector and returns its count. `EStandaloneProfile` hides unfinished inherited profiles until normalization supplies independent modern arguments and a main class.
- `EngineLaunch param` validates the selected modern vanilla or normalized loader profile, player identity, libraries and Java, then uses `CreateProcessW`. Offline UUIDs follow MD5(`OfflinePlayer:<name>`). JVM arguments use a relative-path argument file for Unicode working directories; session identity arguments remain in memory. `EModuleOnly` excludes exact libraries already declared on the effective JVM module path from the relative classpath. Do not remove unrelated libraries or switch the classpath to absolute UTF-8 paths.
- `EInstallCore` installs a vanilla release/snapshot from the source-routed Mojang manifest, or repairs an existing standalone profile marked `offsetNormalized:true` using its local metadata. It verifies the client, libraries/native classifiers and assets, honoring Windows rules and cancellation. `EngineInstall param` wraps it with cleanup and one `WM_APP+2` completion message.
- Raw `inheritsFrom` and legacy `minecraftArguments` metadata are not directly launchable. Loader inheritance is resolved by `ProfileNormalize` before a profile becomes available. Modern metadata support is not a promise that every historical game/loader combination is compatible; Java and loader compatibility still follow the selected versions.

## version_settings.inc, version_page.inc, version_mods.inc and version_actions.inc (0.6)
- Per-version identity is the canonical game root plus validated profile ID. Settings live in `<root>/versions/<id>/.offset-profile.ini`, section `[Profile]`, with `NameHex`, `JavaHex`, `MemoryMiB` and `Isolate`. Hex fields store UTF-16 text. The display name does not rename the profile ID, directory or game metadata. Preserve existing game/loader JSON and global launcher settings.
- `VsRead rootW, idA, record, installed` reads into the caller's `VS_SIZE` record without changing the active UI settings. `installed=1` requires a valid installed modern standalone JSON/JAR; `installed=0` also allows a not-yet-installed profile or not-yet-created game root with shared defaults, checking existing ancestors without creating directories. `VsLoad rootW, idA` loads validated installed settings into `vs*` globals for the UI. Validate IDs, bounded paths and directory/file types; reject reparse paths rather than following them outside the intended tree.
- `VsSave` validates and atomically publishes the current `vs*` settings. An empty Java path inherits global Java; memory `0` inherits global memory, otherwise accept only `512 MiB` through the detected physical-memory limit. Isolation defaults to `0` (shared root); `Isolate=1` resolves game data to `<root>/versions/<id>/game`. Changing isolation does not move, copy or delete old game data.
- `VsResolveData rootW, idA, destinationW, capacity` returns 1/0 with the effective shared or isolated data root, without replacing the UI context. `VsLaunchSettings rootW, idA` applies effective Java/memory and sets `eRuntimeDirW` / `eRuntimeIsolated` for launch. `EngineLaunch` restores global Java/memory and runtime context after success, cancellation or failure. The Java working directory and game-data arguments use the resolved data root; client metadata/JARs, libraries, assets and native caches remain rooted in the original game/profile directories.
- The page opens through Home Manage, Installed Manage or an installed-list double click, with Overview / Settings / Mods tabs. `VersionPageOpen rootW, idA` captures `vmRootW`, `vmIdA` and `vmDataDirW`; merely opening or navigating it never changes global `gameDir` / `selectedVersion`. Overview exposes profile details, effective settings, launch/repair and data/profile/mods/saves/logs/resource-pack folder actions. Main routes paint, click, native command and completion through the page interfaces.
- `VersionPageUse` explicitly selects the viewed root/profile and saves global selection, rolling back if saving fails. `VersionPageLaunch` selects it before launch; `VersionPageBrowseMods` selects it before opening the ordinary download page. The repair worker temporarily supplies the viewed root/profile to `EInstallCore`, restores the original globals and posts exactly one `WM_APP+2` completion. UI mutation stays disabled while a worker owns shared engine/mod state.
- On an active version page, F5 launches its profile, F6 repairs it, and Ctrl+S saves that profile's settings. Outside this page retain the existing global/navigation shortcuts.
- `version_mods.inc` reuses the bounded `modLocals` model, scans the viewed version's actual data root and shows that path. `VmModsWorker` captures the data root before starting; it scopes the common mod manager to that root and clears the scope on every completion. Main calls `VmModsFinishUI` through `VersionPageFinishUI` once. Shared mode intentionally exposes the shared mods directory; page navigation alone does not create isolation.
- Native regression suites are `version-settings`, `version-page`, `version-mods` and `version-actions`. Under `-JavaProbe`, `version-launch` uses actual JVM processes to check per-profile Java/memory, shared/isolated working directories, root libraries/assets and restoration after launch/cancel/failure. Keep these results distinct from native GUI checks and actual Minecraft rendering evidence.

## version_types.inc, versions.inc and versions_ui.inc
- Fixed capacities: 4096 release/snapshot catalogue records, 1024 loader versions, and 64 queue records. See `version_types.inc` for byte offsets. Loader kinds are 0 vanilla, 1 Fabric, 2 Forge, 3 NeoForge, 4 Quilt.
- `VersionsFetch` / `VersionsParse` publish a complete validated catalogue without destroying an existing good list on failure. The native UI supports type/query filtering, multiple selections, loader/version choices, installed profiles and queue controls.
- `VersionQueueAdd baseIdA, kind, loaderVersionA` deduplicates jobs; completed, failed or cancelled entries can be scheduled again. Queue states are pending, running, complete, failed and cancelled. `VersionQueueRun param` processes jobs serially while the UI disables mutation, preserving the previously selected launch profile.
- For a loader job, install the vanilla base, call `LoaderInstall`, call `ProfileNormalize`, then load the child and run `EInstallLibraries` to verify its libraries and extract native classifiers into the child's `offset-natives`. Only then mark the job complete. The queue worker posts one completion message for the whole run; internal helpers do not post per-item completion messages.

## loaders.inc and profiles.inc
- `LoaderFetchVersions baseIdA, kind` reads official Fabric/Quilt metadata, Forge version metadata or NeoForge Maven versions, validates compatibility and sorts loader versions. Do not assume a service's array is already ordered. Snapshot support depends on the loader service; Forge/NeoForge mappings must reject unsupported snapshot or unknown coordinate schemes.
- `LoaderInstall baseIdA, kind, loaderVersionA, targetIdA` obtains Fabric/Quilt profile JSON directly. Forge/NeoForge jobs download the official installer JAR using its repository SHA-1, inspect its version metadata, and run the configured Java with `--installClient <gameDir>`. Reuse existing launcher profile configuration; create a minimal file only when both recognized launcher-profile files are absent. Installer cache/logs live under `.offset-install`. Cancellation terminates only the installer/extractor child process owned by this job.
- `ProfileNormalize childIdA, baseIdA` creates independent modern metadata from a validated child and vanilla parent. Child fields override parent fields; JVM/game arrays are combined, and child Maven coordinates replace matching parent libraries. Name-only Fabric/Quilt libraries obtain Maven checksums; local installer outputs with missing hashes can be hashed after installation. An explicitly invalid checksum fails.
- Normalization writes `offsetNormalized:true` and `offsetBase:<base id>`, preserves the original child as `offset-original.json` without overwriting an existing backup, and creates a client JAR hardlink with copy fallback. Metadata publication is atomic. Loader installation also preserves an existing profile as `offset-before-install.json`. These helpers return 1/0 and do not post worker completion messages.

## catalog.inc, packs.inc, pack_import.inc and packs_ui.inc (0.5 / 0.7 modpacks)
- `catalog.inc` owns separate `packProjects` / `packFiles` arrays using the existing `MP_*` / `MF_*` layouts, 20 projects and 32 files. Online catalogue search is Modrinth-only (`packProvider` is forced to 0); the old CurseForge search/API path and provider switch are not exposed. `packQuery`, `packGameVersion`, `packLoader`, `packOffset` and the selected indexes are input; empty game/loader filters mean all. `PackSearch` / `PackVersions` return 1/0 synchronously and expose only bounded archive records. `PackDownload index, destinationW` verifies the selected archive with its published SHA-1.
- Include catalogue and detail modules after `modrinth.inc` / `curseforge.inc`: their bounded string, URL, JSON-array and sensitive-header helpers are reused. Authentication headers go only to the official API through nonredirecting `HttpRequest`; ordinary archive/file transfers use `HttpDownload`.
- `PackInstall archivePathW, destinationW` installs a Modrinth format-1 `.mrpack`, CurseForge manifest-version-1 ZIP, or supported Prism / MultiMC exported instance as a new independent game directory. It saves/restores shared `gameDir` and `selectedVersion`, returns 1/0, and does not post worker completion messages. On success, `packInstalledName` and `packInstalledVersion` describe the published instance. `packLastError` records a Win32 error from a failed final rename for diagnostics. `PackInstallChecked archivePathW, destinationW, expectedSha1A` binds confirmation to the reviewed archive by checking its SHA-1 while the archive sharing lock is held, before creating a stage; a changed archive fails and requires reinspection.
- `PackInspect archivePathW` in `pack_import.inc` returns 1/0 without writing files, creating instances or downloading artifacts. Read the manifest through a bounded extractor pipe after independent ZIP validation. Recognize manifests at the root or beneath one common wrapper directory by content, not extension; reject ambiguous roots. Publish `packInspectReady=1` only after the locked archive's SHA-1 and complete metadata are available: `packInspectFormat` (1 MR, 2 CF, 3 Prism/MultiMC), UTF-8 `packInspectName` / `packInspectBase` / `packInspectLoader`, `packInspectLoaderKind`, `packInspectHash`, `packInspectFiles` and `packInspectBytes`. Consumers copy this read-only preview before starting another operation.
- Validate ZIP central/local names, codecs, sizes, descriptors and permitted extra fields before extraction. Refuse traversal, drive/absolute paths, DOS-device components, case aliases, links/reparse points, encryption, ZIP64 and unsupported structures. Current bounds are 512 MiB archive size, 128 MiB per-entry declared size, 2,147,483,647 bytes aggregate declared size (approximately 2 GiB), 4096 archive entries and 4096 downloaded files. These are supported-format limits, not a claim that arbitrary ZIPs or formats are accepted.
- Install into `destinationW + .offset-stage`, owned by an exact archive-SHA-1 `.offset-pack-stage` marker; resume only matching owned stages with safe directory trees. Existing final directories are never replaced. Extract into the stage's `.offset-archive`, verify listed client files, install the base game and loader through existing engine/normalizer helpers, then apply common/client overrides. Payload cannot replace launcher-owned versions, libraries, assets, profiles or `.offset-*` roots. Write `.offset-pack.json` with `complete:true`, name and installed version before the final directory rename. Publish only after every required step succeeds; failed/cancelled stages retain reusable cache and remain unlisted as installed instances.
- MR files use allowed HTTPS hosts and SHA-1, skip `env.client=unsupported`, and retry alternative trusted download URLs. CF required file IDs resolve through official project/file API metadata, including distribution and class checks; class 6 maps to `mods`, 12 to `resourcepacks`, and 6552 to `shaderpacks`. A missing/blocked required file fails the install; never synthesize a CDN URL. Optional CF files are skipped. Only recognized Minecraft and loader dependency formats are accepted.
- Prism / MultiMC reads `mmc-pack.json`, `instance.cfg` and exactly one `.minecraft/` or `minecraft/` payload directory. Accept `net.minecraft` and the four supported loader components. LWJGL / intermediary components are accepted only as dependency-only declarations and rebuilt from official game / loader metadata; refuse explicitly selected custom runtime versions, unknown components, `patches/`, `jarmods/`, and nonempty pre-launch / post-exit / wrapper commands. Do not execute archive scripts or migrate foreign Java paths, JVM arguments or accounts. Ordinary safe payload data may be copied after rebuilding the game and loader.
- `packs_ui.inc` owns native search/version/installed-instance controls, the third import-preview tab, and the `PackWorker` completion wrapper. `PackUiInit` derives EXE-adjacent `downloads/packs` and `instances` directories from `iniPath`; `PackBuildPaths` uses provider/project/version IDs for stable catalogue paths. `PackImportLocal` accepts `.mrpack` / `.zip` through a native file picker; action 5 only inspects, and explicit confirmation uses action 4 with `PackInstallChecked`. The preview archive and its SHA-1 have separate buffers from catalogue downloads. Main skips generic INI persistence for action 5. Validate an editable ASCII instance-folder component, destination bounds and nonexistence without creating directories. Cancelling the picker preserves the previous preview; clearing or cancelling an inspection cannot install. Reset stale worker results before dispatch so thread-creation failure cannot expose an earlier successful result.
- `PackScanLocal` lists only validated complete markers, up to 128 instances. `PackActivateSelected` rechecks local metadata/JAR paths, updates game directory/current version through existing controls, saves settings, and returns to launch. Installing a pack does not merge its data into the previously selected game directory. `pack-import` and `pack-import-ui` cover format handling, confirmation identity, unsupported structures, cancellation, read-only inspection, safe names and UI completion separately from live-service or GUI evidence.

## pack_export.inc, pack_export_zip.inc and pack_export_ui.inc
- Include `pack_export.inc` after the pack importer, version-settings and loader helpers; it includes the original ZIP writer. `PackExportInspect rootW, idA, includeSaves` returns 1/0 synchronously, only reads the effective `VsRead` / `VS_DATA` source, and never changes global `gameDir` / `selectedVersion`. Set `peIncludeMods`, `peIncludeConfig` and `peIncludeResources` to 0/1 before inspection; all default to 1 and `includeSaves` defaults to 0. Publish `peReady`, `peFileCount`, `peTotalBytes`, `peDataDirW` and bounded UTF-8 `peSummaryA` only as inspection output. The summary contains a partial relative-path list; counts include the entire selected payload.
- Mods selects `mods`; Config selects `config`, `defaultconfigs`, `kubejs`, `scripts` and `options.txt` / `optionsof.txt` / `optionsshaders.txt`; Resources selects `resources`, `resourcepacks`, `shaderpacks` and `datapacks`; Worlds selects `saves`. Recursion rejects reparse points and unsafe paths. Exclude launcher/runtime roots, logs, crash reports, caches, screenshots, `servers.dat`, `.offset-*` and known account / credential filenames even beneath selected content directories. These filename exclusions are not a general detector of private mod data.
- `PackExportBuild` consumes the source recorded by inspection plus `peFormat` (1 Modrinth, 2 CurseForge, 3 Prism/MultiMC), UTF-8 `peNameA` (256 bytes), `peVersionLabelA` (128), `peAuthorA` (256 bytes) and UTF-16 `peDestW`. It rescans and revalidates the source before writing, rejects invalid metadata, and never copies launcher settings, accounts, Minecraft binaries or Java. Local CurseForge ZIP format compatibility remains available for import/export; it is not an online search or API integration. MR / CF manifests have empty remote file lists and carry local payload under `overrides/`; Prism emits standard components, `instance.cfg` and `.minecraft/`. `offset-export.json` records the entered metadata. Do not fabricate platform project/file IDs or download URLs, upload a pack, or claim platform publication compatibility from local format compatibility.
- `ExZipBegin`, `ExZipAddMemory`, `ExZipAddFile`, `ExZipFinish` and `ExZipAbort` implement bounded UTF-8 ZIP/store with CRC32, without external writer dependencies or ZIP64. Limit payload to 4093 files, 128 MiB per file and 512 MiB complete archive including headers / metadata. Pin source files while reading and recheck directory ancestry. Write an owned `CREATE_NEW` temporary output, run the real `PackInspect` on the completed archive, then publish with a nonreplacing rename. Destination must be outside the source game / data roots; existing files and directories are never replaced. Failure/cancellation removes only the temporary file owned by this operation.
- `pack_export_ui.inc`, included by `packs_ui.inc`, owns the fourth pack tab and a source selector independent of the current launch selection. Source / content changes invalidate the preview and destination; metadata remains a local draft. Default version is `1.0.0`. A completed preview is required before opening the native save dialog or confirming export. Worker action 6 inspects; action 7 builds; both use the existing busy/cancel guard and reset result state before dispatch. Main skips generic INI persistence for actions 5, 6 and 7. Start verifies that source identity and group flags still match the reviewed backend state. Cancelled save selection preserves the previous destination; successful build enables an explicit folder action.
- The PCL-inspired flow is metadata, content categories, preview, save location and background export. This implementation provides three self-contained format choices and category switches; it does not implement PCL's per-file advanced rules, launcher bundling or platform upload. `pack-export-ui` exercises real hidden native controls and confirmation state; `pack-export` / `pack-export-zip` cover backend format / writer behavior separately from GUI and round-trip evidence.

## launch_log.inc and logs_ui.inc (0.7)
- Define `OFFSET_LAUNCH_LOG` to integrate logging into `EngineLaunch`; standalone engine tests without the flag retain their existing launch behavior. Capture effective version, Java, memory and actual data directory before per-version overrides are restored. Never record the full session command line, environment or authentication request bodies. Merge child stdout / stderr into a noninherited reader pipe and continue draining after the retained-output bound, avoiding a blocked JVM. Close only handles belonging to this run; launching and cleanup must preserve the original engine result and global-restoration contracts.
- Write UTF-8 files under the effective data directory's `.offset-logs/`, with a unique time / tick / serial stem, `.log` for launch output and `.txt` for abnormal-run reports. Save through a private temporary file and atomic publication; set ready flags only after successful publication. Each file is at most 4 MiB, retained Java output at most 3 MiB. Nonzero process exit, preparation or CreateProcess failure can produce a report; cancellation retains a launch log without claiming a crash. Record the process exit code, using `FFFFFFFFh` when no child was created, and meaningful Windows API error codes. Preserve `launchLogSaveError` on persistence failures.
- On abnormal runs, attach only files modified at or after this launch's timestamp: `logs/latest.log`, the newest eligible `crash-reports/*.txt`, and the newest eligible `hs_err_pid*.log` in the actual data directory. Each attachment contributes at most its last 1 MiB and is marked when truncated. A prior run's crash must not be relabelled as a current report.
- Replace the current known `authToken` and `curseApiKey` throughout generated text, including matches split across pipe / file-read boundaries. This is exact known-credential redaction, not a claim to detect arbitrary secrets in third-party output. Keep credential copies transient and wipe them during cleanup. A saved or exported report must not contain those known raw values.
- Expose ready / error / path globals to the UI. `LaunchLogRead kind, destinationA, capacity` reads bounded display text for kind 0 launch / 1 report; `LaunchLogExport destinationW` does not replace an existing file. `LaunchLogExportTo destinationW, allowReplace` preserves the convenience preference for an available report; `LaunchLogExportKindTo kind, destinationW, allowReplace` exports the UI's current launch / report tab. Replacement requires explicit native-save confirmation and atomically publishes a `.txt` / `.log` destination; refuse source equality, directories and reparse targets. `LaunchLogDiscover dataDirectoryW` finds the newest completed run log and only its report with the same run identifier; discovery must not advance the run serial or trigger a new-crash notification.
- `logs_ui.inc` provides the eighth navigation page (`Ctrl+8`), native read-only launch / crash tabs, open-folder and explicit export actions. Completion of a newly generated abnormal report opens that report once; ordinary refresh or discovery does not replay the notification. Keep native GUI checks and actual Java stdout / stderr / exception / start-failure probe evidence distinct. `launch-log` and `logs-ui` are the corresponding regression suites.

## ui_gfx.inc and i18n.inc (0.4 interface, extended in 0.5)
- Drawing uses logical 96-DPI coordinates on the 1120x760 canvas. Shapes go through GDI+ helpers (`FillRR`, `StrokeRR`, `LineA`, `ArcA`, `Card`, `Field`, `Button`, `Segmented`, `DrawLogo`); text uses `Text` / `TextC` / `TextR` / `TextDraw` (GDI ClearType). `A_*` constants are ARGB, `T_*` are COLORREF. Helpers must not leave GDI+ state changed; register clickable custom areas with `HotAdd` during paint so hover/press feedback works.
- Motion: springs (`AnimSet slot,target,immediate` / `AnimGet`), `StartTransition` before a page or tab change followed by `SyncPage`; native controls stay hidden until the transition settles. The timer stops itself when nothing moves; busy indicators animate only while the window is foreground.
- Startup (`splash.inc`): `SplashInit` runs before the window is created (Home page only, motion on, `StartupAnimation` not 0). While `splashActive` is set, `SyncPage` keeps controls hidden and `PaintSplash` draws last; its final frame equals `PaintHero`, so changes to the hero card geometry (card 252,124,836x172; logo box 905,155,110) must update the `SPLASH_*` end constants. `SplashFinish` hands off and is also the skip path.
- Sidebar (`sidebar.inc`): collapse amount is spring slot 8 (`ANIM_SLOTS = 10`). Pages keep drawing in expanded-layout coordinates; `Paint` sets `gOffX = contentX` (0 or `CONTENT_SHIFT`), `HotAdd` records offset rectangles, `Click` subtracts `contentX` before page handlers, and `ShiftControls` moves every direct child window once the spring rests. New page controls must be created through `NewControl` before `ShiftControls` runs in `CreateControls`; do not position controls with absolute `SetWindowPos` without adding `controlsX`.
- Window and frames: the window keeps `WS_CAPTION` for DWM (shadow, corners, taskbar) but `WM_NCCALCSIZE` returns 0, so the client is the whole window; `WM_NCHITTEST` returns `HTCAPTION` in the top band (y < 108 logical) where no `HotAdd` area exists, so register custom clickable areas there. Minimize / close are custom (`PaintWindowButtons`, `WindowButtonHit`).
