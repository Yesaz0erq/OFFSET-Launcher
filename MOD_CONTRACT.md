# OFFSET 0.7 mod and modpack feature contract

Read `CONTRACT.md` and source. Launcher runtime code remains original FASM x86; Java is supplied separately for Minecraft and official loader installers. Root coordinates main.asm/imports/strings/build/tests runner/docs. Each module has unique data/code sections, uninitialized buffers at the end. Include `src/mod_types.inc` and, for version/loader integrations, `src/version_types.inc` before module sections. Use stdcall procedures, win32ax.inc and the existing 256 KiB committed stack.

## Shared model (defined in mods.inc, local manager agent)
`modProvider dd 0` (0 Modrinth,1 CurseForge), `modQuery rb 512`, `modGameVersion db '1.21.1',0 with capacity64`, `modLoader db 'fabric',0 capacity16`, `curseApiKey rb 256`, `modCancel dd 0`; `modProjectCount dd`, `modFileCount dd`, `modLocalCount dd`, `modSelectedProject dd -1`, `modSelectedFile dd -1`, `modSelectedLocal dd -1`; `modProjects rb MP_SIZE*20`, `modFiles rb MF_SIZE*32`, `modLocals rb ML_SIZE*512`. See mod_types.inc exact offsets/capacities. Project/file indices zero based. Strings UTF8, local ML_NAME UTF16 <=279 code units. All fields NUL terminated. MF_DEPS may describe required dependency IDs, MF_REQUIRED numeric count. Provider routines MUST validate/truncate strings safely and never publish oversized string buffers or unsafe filenames. Clear arrays/count before parsing new response. UI cannot change globals while worker runs.

## Provider modules
Modrinth agent owns src/modrinth.inc; public `ModrinthSearch` and `ModrinthVersions`. CurseForge agent owns src/curseforge.inc; public `CurseSearch` and `CurseVersions`. These are synchronous worker routines returning eax1 success /0 failure, set status via `SetStatusA pUtf8`, do NOT post WM_FINISHED (root worker wrappers do that). Query globals above are input. `Versions` reads modSelectedProject and selected record. Fill modProjects/modProjectCount or modFiles/modFileCount. Only officially compatible Minecraft gameVersion+loader files. Validate actual returned game_versions and loaders when reasonable; no accidental incompatible file. Filters supported: fabric/forge/neoforge/quilt. Searches max20 projects/page initially, add `modOffset dd0` for pagination (per20); `modTotal dd0` returned total. Version lists max32 latest matching entries. Use official APIs and respect thirdparty distribution restrictions. Require SHA1 for downloadable artifact. Do not guess CurseForge download URL if server returns null; mark MF_BLOCKED1 and leave MF_URL empty. MP_URL website project URL, bounded and official domain. CF API key only x-api-key header to api.curseforge.com, no redirects, never logs. No key borrowing. Headers wiped after use. CF no key returns clear Chinese status.

## Helpers implemented by mods.inc agent, available to providers
`ModAppend dstA, capacity, srcA`: returns1/0, bounded append, 0 on overflow (does not overrun). `ModUrlEncode srcA, dstA, capacity`: RFC3986 UTF8 percentencoding, returns encoded length or -1 on truncation. `ModSafeFilename nameA`: returns1 only safe basename ending .jar, reject separators/traversal/colon/controls/reservedWindowsnames/trailingdots/spaces and oversized names. `ModIsSha1 strA`: returns1 only40hex chars. `ModTrustedUrl urlA, provider`: returns1 only official HTTPS CDN for relevant provider (cdn.modrinth.com; *.forgecdn.net with strict host boundary and no credentials), else0. `ModNumber srcA`: accepts positive decimal string and returns value (0invalid). Optional helpers coordinate directly. `SetStatusA` main thread-safe callback; shared common.inc supplies HttpRequest/HttpDownload/JSON helpers per CONTRACT.md. Provider User-Agent identifies the current OFFSET release and project context, without invented contact URLs.

## Local manager (mods.inc agent)
`ModsInit`: set defaults. `ModsDataRoot destinationW, capacity`: resolve the effective data root, using an explicit version-page worker scope when active, otherwise `VsResolveData(gameDir, selectedVersion, ...)` in the integrated launcher; standalone module tests retain the legacy `gameDir` fallback. Return1/0, reject invalid or overlong roots, and do not mutate global `gameDir` or `selectedVersion`. `ModsSetDataRoot rootW` sets the explicit scope; passing0 clears it. A rejected explicit scope must fail closed rather than fall back to another profile.

`ModsScan`: scan `<dataRoot>/mods` for *.jar and *.jar.disabled, populate locals <=512; no UI manipulation. `ModsToggle index`: rename .jar to .jar.disabled or back, no overwrites; returns1/0 and status. `ModsTrash index`: move selected exact local filename into `<dataRoot>/mods/.offset-trash` using collision-safe name, recoverable; no permanent delete. `ModsInstall index`: validate record, file+URL+SHA1, download into `<dataRoot>/.offset-mod-cache/hash.jar` then verify hash + ZIP signature, move into `<dataRoot>/mods` without overwriting existing different file. Scanning, toggling, trash, cache/final downloads and folder actions must all use the same resolved data root. Reuse identical file, preserve old disabled copy and existing backups. No automatic unrequested updates/dependency execution. Describe required dependencies in successful status so the user can install them.

## Version/loader integration in 0.3
Loader installation belongs to version management, not `ModsInstall`. `versions.inc` provides the release/snapshot catalogue and serial installation queue; `loaders.inc` obtains compatible Fabric, Quilt, Forge and NeoForge versions and installs the selected loader; `profiles.inc` resolves its inheritance into standalone modern launch metadata. Forge/NeoForge use their official installer JARs on demand with the user's configured Java. A successful loader job includes child-library verification and native extraction. Older metadata and unavailable game/loader combinations can still be unsupported.

`ModSyncSelectedProfile` in `mod_profile.inc` reads the selected installed profile on the idle UI thread. It validates `offsetNormalized` / `offsetBase` and recognized loader Maven coordinates, updates the mod game/loader filters and clears stale search results when the selection changes. Metadata remains under the game root's `versions/<id>` directory. The UI may still be edited for another intended search target; filter edits alone do not select a different download destination or guarantee runtime compatibility.

## Per-version management in 0.6
`version_settings.inc` identifies settings by canonical game root plus profile ID and stores them in `<root>/versions/<id>/.offset-profile.ini`. Shared data is the default (`Isolate=0`); optional isolation (`Isolate=1`) changes the effective data root to `<root>/versions/<id>/game`. Switching modes does not automatically move, copy or delete existing mods, saves or configuration. Client, libraries and assets caches remain under the original game root. `VsResolveData rootW, idA, destinationW, capacity` supplies the effective data root without modifying the active UI draft, including shared defaults when a profile has not yet been installed or its root has not yet been created. It checks existing ancestors, creates no directories and rejects unsafe existing INI files or paths.

The per-version page opens through Home Manage, Installed Manage or a double click, with Overview / Settings / Mods tabs. Merely opening a page does not change the current launch profile. Its settings include a display-only name, Java (empty inherits global), memory (`0` inherits global; otherwise `512 MiB` through detected physical memory) and isolation. F5 launches the viewed version, F6 repairs it, and Ctrl+S saves its settings. Launching or entering mod downloads explicitly selects that version; ordinary mod-center operations then use its resolved data root.

`version_mods.inc` uses `vmRootW`, `vmIdA` and `vmDataDirW` from `version_page.inc`, shows the actual path and reuses `modLocals` for refresh, enable/disable, recoverable trash and folder navigation. Expose `CreateVmModsControls`, `VmModsShow` / `VmModsHide`, `VmModsEnable`, `VmModsPaint`, `VmModsClick`, `VmModsCommand` and `VmModsFinishUI`. Capture `vmDataDirW` into `vmModsWorkerRootW` before `VmModsWorker` starts; set the explicit mod root only for the operation and clear it before posting one completion. `VersionPageFinishUI` forwards that completion once. The single-worker busy guard protects shared arrays; refresh the relevant local list after changing context so a prior page's rows cannot target another directory.

## Modpack catalogue and installation in 0.5 / 0.7
`catalog.inc` reuses the MP/MF record layout through separate `pack*` state and buffers. `PackSearch` and `PackVersions` query Modrinth `project_type:modpack` or CurseForge class 4471, up to 20 projects and 32 archive versions. Game and loader filters may be empty. `PackDownload index, destinationW` verifies the provider-published SHA-1 for `.mrpack` or `.zip`; null URLs, invalid hashes and distribution opt-outs remain unavailable through the API. These routines are synchronous, return1/0, and do not post worker completion messages.

`PackInstall archivePathW, destinationW` in `packs.inc` supports the Modrinth format-1 index, CurseForge manifest-version-1 export structure, and supported Prism / MultiMC instance ZIPs. It validates ZIP/local-central names and permitted metadata, downloads listed client files with hashes, installs the declared base/loader using existing engine helpers, and applies safe overrides. CF project/file metadata identifies the permitted output category: class 6 JARs under `mods`, class 12 ZIPs under `resourcepacks`, and class 6552 ZIPs under `shaderpacks`. Unknown classes, unsupported dependencies, or blocked required files fail explicitly. Never guess a restricted URL, borrow an API key, or assume every downloaded archive is a JAR.

`PackInspect archivePathW` in `pack_import.inc` recognizes root-level manifests or one common wrapper directory by archive contents, independent of `.mrpack` / `.zip` extension. It validates and reads metadata without downloading files, creating an instance or writing an extracted manifest. It publishes the detected format, name, base game, loader, counts and archive SHA-1 only when `packInspectReady=1`. Local CurseForge structure inspection does not require a key; actual required-file resolution retains the official API-key and distribution rules. A UI confirmation must use `PackInstallChecked archivePathW, destinationW, expectedSha1A`, which compares the reviewed SHA-1 while the archive is locked before preparing a stage. Replacing the archive after inspection requires reinspection.

Prism / MultiMC imports read `mmc-pack.json`, `instance.cfg` and one `.minecraft/` or `minecraft/` payload tree. Accept the modern Minecraft component and supported Fabric / Forge / NeoForge / Quilt components. Dependency-only LWJGL / intermediary declarations are rebuilt through official metadata; explicit custom runtime versions, unknown components, `patches/`, `jarmods/`, and nonempty pre-launch / post-exit / wrapper commands are rejected. Do not execute third-party installation scripts or carry over another launcher's Java paths, JVM arguments or account configuration. Ambiguous manifests or multiple payload roots fail rather than guessing a target.

Archive limits are 512 MiB compressed size, 128 MiB per declared uncompressed entry, 2,147,483,647 aggregate uncompressed bytes (approximately 2 GiB), 4096 ZIP entries and 4096 manifest files. ZIP64, encryption, links / reparse points and unsafe path aliases remain unsupported. Do not interpret these bounds as acceptance of arbitrary ZIP formats or server installers.

Pack installation uses a private sibling `.offset-stage`, identified by the exact archive SHA-1. Resume only a matching owned, non-reparse stage. Final existing instances are not replaced. A complete `.offset-pack.json` marker is written only after files, game and loader preparation succeed; directory rename then publishes the instance. Cancellation/failure retains private cache without switching the launcher's current directory or falsely exposing the stage as installed. Ordinary version profiles share their selected `gameDir` by default, or use `versions/<id>/game` when explicitly isolated; installed modpacks each have an independent root under EXE-adjacent `instances`.

`packs_ui.inc` owns native search, version and installed-pack controls, the third import-preview tab, EXE-adjacent `downloads/packs` cache paths, worker completion and explicit activation. `packUiAction=5` runs inspection only; explicit confirmation uses action 4 and its copied archive hash. Import archive / metadata buffers are separate from catalogue download buffers. The editable ASCII destination-folder name must be safe, bounded and absent; no file or directory is created by name validation. Main omits global INI persistence for inspection. Cancelling file selection preserves the prior preview, clearing discards only the preview, and worker result state is reset before dispatch. Activation revalidates the completed local profile and changes `gameDir` / selected version through the existing settings flow. Do not automatically merge pack mods, saves or configuration into a previous game directory.

## Local modpack export
`pack_export_ui.inc` provides the fourth pack tab through `packs_ui.inc`. Its dropdown scans installed versions of the current game root but does not change the launcher's selected version; data routing uses each source version's effective shared / isolated `VsRead` path. The form follows the PCL export flow of name/version, content selection, destination and background task, with an explicit read-only preview. Name/version/author remain UI drafts; the version defaults to `1.0.0`. Mods, Config and Resources default enabled; Worlds defaults disabled. Changing source or categories invalidates the preview and destination. The selected source tuple and category flags must still match when the user confirms.

`PackExportInspect rootW, idA, includeSaves` is a synchronous read-only scan. Set `peIncludeMods`, `peIncludeConfig` and `peIncludeResources` before calling it. `peReady`, `peFileCount`, `peTotalBytes`, `peDataDirW` and UTF-8 `peSummaryA` are preview outputs. Mods includes `mods`; Config includes configuration / default configuration, KubeJS, scripts and supported options files; Resources includes resource packs, shaders, resources and data packs; Worlds includes `saves`. Known account / credential filenames, `.offset-*`, logs, caches, runtime/library roots, screenshots and server lists remain excluded. This is bounded category selection, not per-file PCL rule editing or arbitrary private-data discovery.

`PackExportBuild` rescans the recorded source and reads `peFormat`, bounded UTF-8 `peNameA` / `peVersionLabelA` / `peAuthorA` and UTF-16 `peDestW`. Outputs are self-contained Modrinth `.mrpack`, CurseForge `.zip` or Prism/MultiMC `.zip`: local selected files are carried in `overrides/` or `.minecraft/`, with standard game / loader metadata. MR/CF remote file lists remain empty rather than inventing project IDs, hashes or download URLs. No platform upload, launcher bundling, game binary or Java redistribution is performed. The original `pack_export_zip.inc` ZIP/store writer introduces no new runtime dependency.

Use an absent destination outside the source instance. Write a private owned temporary file, validate the complete result through `PackInspect`, and publish atomically without replacement. Cancellation/failure preserves the source and removes only this operation's temporary output. Limits are 4093 payload files, 128 MiB per file and 512 MiB complete archive. Actions 6/7 share `PackWorker` and one completion; main must not persist unrelated launcher settings for either action. `pack-export-ui` tests native confirmation, source isolation, save cancellation, metadata conversion, defaults and busy state; backend/writer and exported-pack import checks remain distinct evidence.

## Launch diagnostics in 0.7
`launch_log.inc` captures the game's merged stdout / stderr, effective launch context and exit / start-failure status under the actual data directory's `.offset-logs/`. `logs_ui.inc` exposes the eighth navigation page and explicit read / open-folder / export actions. Save UTF-8 launch logs and abnormal-run reports with the same run identifier through temporary files and atomic publication; only successfully saved files set ready state. A new abnormal report opens automatically once, while reloading an old completed run does not become a new crash.

Keep each file within 4 MiB, retain at most 3 MiB Java output, and take at most the last 1 MiB of each eligible attachment. Continue draining pipe data even after the retained-output bound. Eligible `logs/latest.log`, newest crash-report text, and newest `hs_err_pid*.log` must belong to the current run by modification-time comparison; use the effective per-version / pack data root, never a sibling instance's logs. Cancellation is recorded without claiming a crash.

Redact the current known Minecraft token and CurseForge API key, including matches across buffer boundaries; do not log a complete session command line or environment. This does not automatically identify all possible private text emitted by mods. Export only the sanitized report / log to an explicit `.txt` / `.log` target, never replacing an existing target without confirmation, and reject the source itself, directories and reparse targets. `LaunchLogRead`, `LaunchLogExportTo` and `LaunchLogDiscover` follow `CONTRACT.md`; discovery finds the newest completed run and only its report with the same run identifier.

## Project introductions and MC百科 in 0.5
`ProjectFetchDetails provider, projectIdA, isPack` in `project_details.inc` fetches the official project description and available source metadata for either mods or packs. It exposes bounded UTF-8 title, summary, plain body and metadata buffers; rejects identity/type mismatches, embedded NULs and oversized values; and reuses the same key handling rules for CurseForge. `DetailPlain` strips active HTML content and converts Markdown/HTML paragraphs and entities to native text. It does not translate, execute HTML, or render arbitrary external pages.

`details_ui.inc` presents that body in a read-only scrolling EDIT, with return/cancel, original-site and MC百科 buttons. `McmodSearchUrl` percent-encodes the selected title into the official `https://search.mcmod.cn/s?key=...` endpoint; an empty query opens `https://www.mcmod.cn/`. This is explicit search navigation, not an asserted exact wiki match or an automatic scrape. The website action retains access to images, formatting and links in the original introduction.

Vanilla downloads use the separate Mojang/BMCLAPI source router. Modrinth/CurseForge API keys, CDN restrictions and dependency handling retain their own rules; do not route mod or authentication traffic through vanilla mirrors.

`ModsLoadKey`/`ModsSaveKey`: DPAPI user-scope encrypted binary offset.cfkey beside EXE; no key in offset.ini or source/logs. Save only through the explicit save-key action; a blank key removes only its own saved key file. Wipe plaintext buffers and use LocalFree API on DPAPI memory. API key max255 bytes, reject CR/LF for headers. Main loads the key at startup into the masked EDIT input in the mod page's API panel. Generic `SaveSettings`, searches and close-time auto-save do not persist the key. The function may return0 and set status on errors.

No module mutates another module's file. Send root new imports early. Tests meaningful: provider mocked transport/real JSON handles versions/null URLs/key safety; live Modrinth search+versions+download; local management Unicode paths/collision/toggle/trash/hash. `version-settings`, `version-page`, `version-mods` and `version-actions` cover settings identity/inheritance/bounds, page context, shared/isolated Unicode mod paths, cache/final-download routing, collisions and restoration. The `-JavaProbe` suite adds `version-launch` with actual JVM processes for per-version settings, shared libraries/assets, isolated working directories and global restoration; that probe has passed and does not by itself establish GUI or Minecraft runtime validation. New `pack-import`, `pack-import-ui`, `launch-log` and `logs-ui` suites cover archive inspection / confirmation, supported instance formats, safe destination state, output / report lifecycle and export. Keep fixture, actual JVM, live-service and native GUI evidence separate. Use tests/out only for tests. Existing full vanilla cache remains untouched.
